Date: 2026-10-09. Method: raw HTML fetch (render_page.py --mode never; JSON-LD is server-rendered, no SPA gap), 15 URLs, sequential, read-only. All JSON-LD is in-HTML `<script type="application/ld+json">`; no Microdata or RDFa found. @context is https://schema.org everywhere. No HowTo, SpecialAnnouncement or WebApplication (correct).

Points are lost on entity wiring, thin college entities, a placeholder in FAQ text, incomplete Dataset metadata, and little markup that is eligible for a Google feature.

## 3. Findings (priority order)

### F1. HIGH (data quality): placeholder "—" inside FAQ answers and visible copy on UG college pages
`/mbbs-india/colleges/aarupadai-veedu-medical-college-pondicherry-ug` and `...abhishek-mishra...-ug` FAQ answer (in JSON-LD and in visible HTML):
"From ₹19.50 lakh a year on a — seat to ₹30.00 lakh on a — seat."
The quota label is null for UG fees (documented in CLAUDE.md), and the template prints a dash where the quota should be. This breaks the "no placeholder text" rule on up to ~1,700 UG pages, and the answer reads as unfinished. Fix in `lib/collegeSeo.ts`: when the quota is null, drop the "on a X seat" clause: "Fees run from ₹19.50 lakh to ₹30.00 lakh a year across the listed seats; the published schedule does not say which quota each fee belongs to."

### F2. MEDIUM: paywall markup is valid and the selector matches, with caveats
- Verified on anonymous HTML: `.ah-gated-depth` exists (on `div[data-testid="locked-summary"]`) on UG college, PG college and branch pages. The JSON-LD cssSelector `.ah-gated-depth` matches a real element. PASS.
- Caveat A: for an anonymous visitor the element carrying the class is the free summary box, not the withheld table. The table (`GatedSeatTable` / `CollegeCutoffs`) carries the same class only when rendered (confirmed in source, `src/components/colleges/CollegeCutoffs.tsx:142`, `src/components/seats/GatedSeatTable.tsx:172`). I could not check the verified-crawler view (spoofing is refused, correctly). `paywall.spec.ts` should keep asserting the class sits on the row block in the crawler view.
- Caveat B: page-level `isAccessibleForFree: true` plus `hasPart.isAccessibleForFree: false`. This is valid schema.org, but Google's documented paywall example sets `false` on the page/Article too. Low risk; consider `false` at page level (or test both in Search Console's paywalled-content report). Edit `paywallJsonLd()` in `src/lib/paywall.ts`.
- The WebPage `@id` equals the page URL, while the CollegeOrUniversity node has no `@id` and no link to it; use `#webpage` / `#college` fragments (snippet 5b).
- Predictor, state, SS, cutoff and stipend pages carry no paywall block and no `.ah-gated-depth` element: consistent.

### F3. MEDIUM: college entities are thin and their names are polluted
- PG: `"name": "Aakash Healthcare Super Specialty Hospital, Dwarka, Delhi-110075"` (PIN inside the name; same in breadcrumb, FAQ questions, and ItemList on state pages). UG AYUSH: `"Government Ayurvedic College and Hospital, Patna, Bihar, Kadam Kuan, Patna, Bihar, 800003"` (whole address as name).
- `address` has only region/country (UG) or locality/region (PG). No `postalCode` even when the PIN is known; no `addressLocality` for UG.
- No `@id`, no `sameAs`/official site, no link from the WebPage (`mainEntity`).
- AYUSH/dental/nursing colleges live under `/mbbs-india/colleges/...` and the breadcrumb says "MBBS colleges". Misleading label.
- Honest value statement: Google has no rich result for CollegeOrUniversity. This is entity understanding only, so keep it cheap and correct rather than expanding it.
Fix: strip the PIN/address from `name`, move the PIN to `postalCode`, add `@id` + `mainEntity` (snippet 5b). For AYUSH use a breadcrumb "AYUSH colleges".

### F4. MEDIUM: Dataset markup is the only rich-result-eligible type here, and it is incomplete
Dataset Search needs name + description (present). Missing recommended: `license`, `temporalCoverage`, `keywords`, `dateModified`/`datePublished`, `identifier`/`@id`, `publisher`, `version`; `DataDownload` lacks `name`.
Structural: all 9 Datasets sit on the `/data` hub, but each `url` points to another page (`/neet-ug-cutoff`, `/bds-india`, `/md-ms-india/stipend`, ...) that carries no Dataset markup (checked `/neet-pg-cutoff` and `/md-ms-india/stipend`: only FAQ/WebPage/Breadcrumb). Two datasets share the same `url` (`/neet-pg-cutoff`). Put each Dataset on the page it describes, or at least give each a distinct `@id`. `creator` is an anonymous Organization; reference `/#organization`. A licence is the owner's decision (CLAUDE.md says none is claimed); without it the dataset is just not labelled "licensable" in Dataset Search. Do not invent one.

### F5. LOW: ItemList bloat and bad item names
`/ayush-colleges`: 60 KB, 169 items whose `name` is the full address string. `/md-ms-india/states/karnataka`: 44 KB, names with PIN codes. No rich-result benefit (not eligible). Either remove, or clean the names and cap the list; as is it inflates HTML on every request. Item `url`s resolve to college pages (good).

### F6. LOW: Report is minimal
`/reports/neet-pg-stipend-2026`: Report has headline, datePublished, author, publisher, but no `image`, `dateModified`, `mainEntityOfPage`; publisher Organization has no `logo`. Article-type markup gives no special SERP feature today, but helps title/date/image understanding and Discover. Add the fields (snippet 5d). Page `og:type` is `website`; `article` would match. No visible `<time>` element was found.

### F7. LOW: Organization is homepage-only and inner pages declare no publisher
Inner pages never reference `/#organization`. Dataset and Report each re-declare an anonymous Organization. Link everything to the one node by `@id`.

### F8. INFO: FAQPage everywhere (not a bug)
FAQPage on college, branch, state, cutoff, stipend, SS and AYUSH pages is valid. No Google SERP benefit; any AI-search benefit is unconfirmed. Do not add more for SERP reasons. Content is page-specific and visible, so keeping it is harmless. For genuine user Q&A use QAPage, not FAQPage.

### Things that are correct
BreadcrumbList on all 13 page types; no deprecated types; no relative URLs; dates ISO 8601 (`2026-10-08`); `@context` https; no WebApplication/HowTo; WebSite correctly has no SearchAction; no hreflang as intended; Organization logo is square and over 112 px.

## 4. Missing opportunities that are actually eligible

1. **Dataset on its own pages** (F4): the only type with a real Google surface (Dataset Search). Highest value.
2. **Organization completeness** (knowledge-panel inputs): legalName, foundingDate, and `address` only if there is a real office. Do not add LocalBusiness without a physical location. Add X/LinkedIn to `sameAs` when those profiles exist (admin settings `social.*` flow in automatically).
3. **Article-style Report completion** (F6). No rich result, but benefits Discover and title/date display.
4. **VideoObject** on `/videos` only if videos are embedded there with real thumbnails and upload dates (not inspected in this scope).
5. Not recommended: Review/AggregateRating from the site's own testimonials (self-serving on Organization, ineligible); Event for MCC rounds (third-party events, risky); HowTo/FAQ for SERP; Course/EducationalOccupationalProgram (retired).
